Troubleshooting lab
Understand the error, find the cause, and fix it with confidence.


01 / DIAGNOSIS
A repeatable debugging process
  1. Reproduce: What input triggers the problem? What did you expect?
  2. Read: Start with the final exception type and message.
  3. Locate: Find the indicated line, and inspect preceding lines and values.
  4. Isolate: Reduce the problem to a small example. Inspect actual values using print(), repr() and type().
  5. Fix one thing: Change the root cause rather than hiding the error.
  6. Retest: Check the original input, normal inputs and edge cases.


02 / TRACEBACK ANATOMY
Read an error message
Illustrative traceback; the browser runner may display different filenames and additional runtime frames.
Traceback (most recent call last):
  File "team.py", line 2, in <module>
    print(team[3])
IndexError: list index out of range
File and line: where to start looking. Code: the failed operation. Last line: exception type and explanation. Read from the bottom up to find the relevant frames in your own code. Syntax errors can point at the next line rather than the actual cause.


03 / ERROR LIBRARY
Find your problem
Search an error name, message or symptom. Inspect the broken code, try a repair and reveal a possible fix.


04 / ENVIRONMENT CHECK
When the problem is not your Python code
  • Wrong interpreter: Check python --version in a terminal and the selected interpreter in VS Code.
  • Missing dependency: Check the active environment and package documentation. python -m pip show package_name is a desktop terminal command, not a Python statement.
  • Wrong file or folder: Save your file and check the working directory.
  • Program hangs: Check for loops that never exit, blocked input or waiting operations. Stop execution before changing code.
  • Pocket Lab runtime: The browser uses Python 3.14, requires internet to initialise, has a timeout and cannot access your PC files or desktop GUI libraries. A runtime loading failure is not necessarily a Python error.
Do not paste passwords, API keys or private data into error reports. Keep the smallest reproducible example and exact error message.
